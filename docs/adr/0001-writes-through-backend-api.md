# ADR 0001: การเขียนข้อมูลทั้งหมดผ่าน NestJS

- **สถานะ:** Accepted (บันทึกย้อนหลังจากการตัดสินใจเดิมใน `ARCHITECTURE.md` หัวข้อ "หลักคิด" ข้อ 1)
- **วันที่:** 2026-09-29

## Context
การจอง มัดจำ เช็กอิน ค่าคอม และโปรโมท มีกฎธุรกิจและต้องทำหลายตารางในธุรกรรมเดียว ถ้าให้หน้าเว็บเขียนตารางตรง (ผ่าน RLS) จะตรวจกฎได้ไม่ครบและแก้ข้อมูลทีละส่วนได้

## Decision
- หน้าเว็บ (`apps/frontend`, `apps/admin`) เขียนข้อมูลผ่าน NestJS เท่านั้น → NestJS เรียกฟังก์ชัน `app_*` / `admin_*` ใน DB (ตรวจสิทธิ์ซ้ำ + ทำทั้งหมดในธุรกรรมเดียว + audit log)
- RLS ไม่เปิดสิทธิ์ INSERT/UPDATE/DELETE ให้ role `anon` / `authenticated` บนตารางธุรกิจ

## Consequences
- กฎธุรกิจอยู่ที่ DB function + NestJS ที่เดียว · หน้าเว็บต้องรอ API ทุกครั้งที่บันทึก
- ต่อยอดโดย [ADR 0002](0002-migrate-direct-db-calls-to-backend-api.md) (ย้ายการ "อ่าน" มาผ่าน API ด้วย)
